Formatter

 

The GExperts code formatter is based on DelFor by Egbert van Nes.

 

For now this help is a copy of the content from the original .hlp file. It is incomplete but better than nothing.

 

Introduction

 

Delfor is a customizable source code formatter. It can improve the indentation, spacing, capitalization and the use of blank lines of Delphi source code. To do so the source code is parsed and lots of special constructs are tested. At default, the style of the Borland source code is followed closely, since this is the most widely accepted style. But formatting of Pascal code is much a matter of taste and debate. Therefore, some alternative rules are included.

 

Limitations and known problems

 

(1) Compiler {$IFDEF} + {$ELSE} directives may be nested to 3 levels and break into blocks of code. After the third nested level the right indentation is not guaranteed.

(2) After some options (aligning, adding line breaks) the indentation might be not correct. Rerunning DelFor can fix the problems.

(3) It is tried to indent function directives after function declarations. In some cases this does not happen.

Indent tab

 

Spaces per indent

        Defines the number of spaces per indent. In all situations the same amount of spaces is used.

 

Extra indent after begin or try:

 If checked an extra indent is added after if-then-else, with-do, on-exception-do and while-do statements:

 

 1. with extra indent:

 

 if i > 10 then

   begin

     l := 3;

   end

 else

   begin

     l := 0;

   end;

 

 2. no extra indent (default):

 

 if i > 10 then

 begin

  l := 3;

 end

 else

 begin

   l := 0;

 end;

 

Extra indent after else in try block:

 If checked an extra indent is added after else in the following kind of try block:

 

 Without option:

 

 try

   DoRun;

 except

   on ESomeException do raise;

   on ESomeOtherException do raise;

 else

   ShowMessage();

 end;

 

 With option:

 

 try

   DoRun;

 except

   on ESomeException do raise;

   on ESomeOtherException do raise;

   else

     ShowMessage();

 end;

 

Extra indent after else in case block:

 

 If checked an extra indent is added after else in the do case statement:

 

 Without option:

 

 case i of

   someValue1:

     DoSomething1;

   someValue2:

     DoSomeThing2;

 else

   DoSomeThingElse;

 end;

 

 With option:

 

 case i of

   someValue1:

     DoSomething1;

   someValue2:

     DoSomeThing2;

   else

     DoSomeThingElse;

 end;

 

Never indent else if

 With this option checked, the indent never increases after else if . The default behavior is that the indent only increases if there is a line feed between if and else

 

 Default:

 

 if t then

   k

 else

   if t then

     j

   else if k then

     t;

 

 With option:

 

 if t then

   k

 else

 if t then

   j

 else if k then

   t;

 

Indent comments

 If this option is checked comments are aligned with the surrounding text, else comments remain unchanged.

 

 With indent comments

 

 if t then

 begin

         {this is

             a comment

            }

     j;

 end;

 

 becomes:

 

 if t then

 begin

   {this is

      a comment

   }

   j;

 end;

 

 

Indent compiler directives

 If this option is checked compiler directives are aligned with the surrounding text, else compiler directives are not indented.

 

 With indent compiler directives

 

 if t then

 begin

            {$IFDEF debug}

 j;

       {$ENDIF}

 end;

 

 becomes:

 

 if t then

 begin

   {$IFDEF debug}

   j;

   {$ENDIF}

 end;

 

 if this option is unchecked the result is:

 

 if t then

 begin

 {$IFDEF debug}

   j;

 {$ENDIF}

 end;

Line breaks tab

 

Always break lines

Line breaks can be added:

 

After var, type etc. :

 

        procedure Test(var i: Integer; const t: Byte);

var t: Integer;

type Pword = ^Word;

 

becomes:

 

        procedure Test(var i: Integer; const t: Byte);

var

        t: Integer;

type

Pword = ^Word;

 

Before end :

 

        if i > 10 then

        begin

        l :=3; end;

 

becomes:

 

        if i > 10 then

        begin

        l :=3;

end;

 

After semi colons (except directives):

 

        if i > 10 then

        begin

        l :=3; k := 3; s:=3;

        end;

 

becomes:

 

        if i > 10 then

        begin

        l :=3;

k := 3;

s:=3;

        end;

 

Note: no lines are added after directives like virtual, abstract, message. A construct like procedure test(k: integer; l: word); forward; remains unchanged.

 

Between else and if:

Add line between else and if. Note that this option is opposite to the After then option. Check the Never indent else if option to prevent indenting.

 

 

After then, else(except else if), do, of :

 

        if i > 10 then l :=3 else if t=0 then k := 3;

        for i:=0 to count-1 do inc(k);

 

becomes

 

        if i > 10 then

l :=3

else if t=0 then

k := 3;

for i:=0 to count-1 do

inc(k);

 

 

Use the Wrap long lines option to break large if then statements. (Wrap text breaks text on then or do if possible).

 

Note that the lines are not removed if this option in unchecked, therefore it is irreversible.

 

Except single lines:

If this option is selected in combination with the previous option (After then, else(except else if), do, of :) then single lines after if then, on : are NOT processed:

 

if i > 10 then l := 3;

case i of

1: t := 0;

2: t := 3;

end;

 

 

Never before then and do :

if i > 10

then

l := 3;

 

becomes

if i > 10 then

l := 3;

 

Note: if the Wrap Long lines option is checked then still might be moved to a single line.

Remove double blank lines

Check this option to remove all double (or more) blank lines. At most one blank line is then allowed.

 

 

Blank lines

Optionally blank lines can be added after

main procedures or

local procedures.

 

 

Wrap long lines

It is possible to let DelFor break long lines into smaller ones.

If a formatted line is longer than the Wrap position, it is tried to break it in smaller lines. If the long line contains then, else or do, the line is broken on that reserved word, otherwise a line feed added after the rightmost space. Lines without spaces and comments are not changed.

Note: the wrapped lines are not always indented correctly. Rerun DelFor to correct this.

1.       hanging after then, else do :

1.       breaks before and after

stays the same if option 1 is selected. If option 2 is checked:

2. hanging:

l :=3

end;

 

3. breaks before and after:

Capitalization tab

Reserved words/Standard directives

The reserved words and standard directives can be written in:

1. lower case

2. UPPER CASE

3. First Character Uppercase

4. remain unchanged.

Note that after one of the first three options is chosen the forth option has no effect anymore. Use the File with user defined capitalization option if you want different capitalization for some reserved words.

If standard directives are used as identifier, in most cases the capitalization is unchanged (the program may fail to recognize the context).

 

Compiler directives

The compiler directives {$XXX} can optionally be placed in upper case. This option is irreversible.

 

Numbers

The hexadecimal numbers and the exponent (E) of real numbers can optionally be placed in upper case. This option is irreversible.

 

File with user defined capitalization

This file contains identifiers and other word that are always written the same way.

 

The file is a text file with words on single lines. Example of the content of such file:

 

True

False

OnClick

 

Using this file

 

i := TRUE;

 

is always replaced with

 

i:= True;

 

The file can be created manual or automatically. If there are reserved words included in the file, the Capitalization of reserved words option is always overridden by this option.

 

The file can be used in different ways:

Do not use file: Nothing happens

Add new words only: With the option Add new words only mode the file is filled automatically with all new identifiers that the program encounters. In this mode all words in the code remain unchanged.

Use file: In this mode the capitalization of all words is changed according to the notation in the capitalization file. If there are reserved words or standard directives included in the file, the notation of the file is always used.

Use file (except standard directivess: This option is the same as the previous one except that standard directives are only changed if these are used as identifiers: e.g.

 

PriVate

property PriVate: Boolean; read FPrivate write FPrivate;

 

changes in:

 

private

property Private: Boolean; read FPrivate write FPrivate;

 

if Private is included in the capitalization file and Standard directives are set to lower case

Add and use: This mode is a combination of Add new words mode and the Use file mode. New words are added automatically.

Add and use (except standard directivess: This mode is a combination of Add new words mode and the Use file (except standard directives) mode.

 

 

With the option Add new words modes the file is filled automatically with all new identifiers that the program encounters. In this mode all words remain unchanged. After editing the file, the Add new words mode should be unchecked to make it work.

Words that should not be changed in the text can best be commented out by adding * before them, e.g.:

 

*i

*nI

True

False

 

The words with a proceeding * are not changed in the text. In advantage over deleting is that the Add words mode doesnt add these outcommented words.

 

Edit button

Use this button to view and edit the file with the idetifiers, see: Edit file dialog.

 

Align tab
 
Align simple end of line comments
Simple end of line comments are comments that are one line, with proceeding code. It can be aligned to a certain position (if possible). E.g.
 
var
i:integer; //comm
j{comm.}:integer; {comm.}
toooooooooooooooo, long:integer; {comm.}
{comm.}
 
changes in (position = 30):
 
var
i: integer; //comm
j: {comm.} integer; {comm.}
toooooooooooooooo, long: integer; {comm.}
{comm.}
 
Align var/const
Var and const declarations can be aligned in the same way: e.g.
 
const
i =0;
var
j:integer;
toooooooooooooooooooo, long:integer;
 
 
changes in (position = 30):
 
const
i = 0;
var
j : integer;
toooooooooooooooooooooo, long: integer;

 

Miscellaneous tab
 
 
Directives in source to prevent formatting
To prevent the formatter from formatting a block of text use the directives.
 
Default:
 
{(*}
... block of code that remains unchanged ...
{*)}
 
You can change the default directives in any other codes (start not necessarily different from end). Of course, the directives should be a Delphi comment.
