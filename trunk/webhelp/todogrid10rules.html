Overview

The configuration allows you to adapt the examination of the files very individually to the respective situation (examination of C files is currently not available). Detailed information about the way of scanning and parsing your source files is explained in this page.

 

What is a token?

In the context of "ToDo Grid" a token is a keyword inserted into the source code that indicates the presence of additional ToDo text information within the program code. To separate this information from the source code to be compiled, the information is marked as a comment in Delphi, using // for single line ToDo and (* *) or { } for multi line ToDo.

The definition of the token is essentially free; however, if you're working within a group of programmers, there will be rules that must be observed. Thanks to the ability to individually activate/deactivate the tokens to be considered for scanning, adaptation to the specific work situation is very easy.

Typical tokens and rules for displaying additional information are presented in the next chapter "Rules of syntax analysis".

 

How to insert (and remove) tokens

To create entries in the source code, you can use the "source code templates" available in the IDE, which can be accessed via Ctrl+J. Alternatively, you can also use the "Code Librarian" expert. In both cases, regular token texts must be created, which can then be quickly inserted later.

In order to keep the time required for scanning the files as short as possible, tokens that are no longer needed should also be removed from the source - a perhaps unspectacular task, but one that should nevertheless be carried out regularly (even within a workgroup)!

 

 

Rules of syntax analysis

 

Structure of ToDo

xx

•Es wird empfohlen das Einfügen und den Aufbau der ToDo-Einträge zu standardisieren und hierfür z.B. in der IDE Strg+J (xxx) oder den "Code Librarian Experten" zu verwenden. Ein Standard-ToDo-Eintrag besteht aus Einleitung // oder (* oder { gefolgt von einem Token, optional einer Priorität, einer Kategori, einem Besitzer, einem Doppelpunkt und einem Erläuterungstext.

•Die Priorität der ToDo-Einträge wird primär von der in OPTIONS definierten Zuordnung von Priorität zu Token festgelegt. In den Sourcen definierte Prioritäten überschreiben die in Options definierten Zuordnungen, wenn nach dem Token ein Leerzeichen, gefolgt von einer Ziffer 0..9 stehen. Die Ziffern 1..5 werden als die 5 deklarierten Prioritätsstufen gewertet, die Ziffern 0 und 6..9  werden als Priorität "Lowest" interpretiert. Steht zwischen Token und Ziffer kein Leerzeichen, wird die Ziffer als Bestandteil des Tokens gewertet.

•Die optionale Kategorie (Category) des ToDo-Eintrags wird durch den Parameter  -c  festgelegt. Der direkt nach  -c  stehende Text darf keine Leerzeichen oder Trennstriche enthalten. Die Begrifflichkeit ist grundsätzlich frei definierbar, im Interesse einer guten Auswertbarkeit sollte die Definitionsmenge so klein wie möglich sein.

•Der optionale Besitzer (Owner) des ToDo-Eintrags wird durch den Parameter  -o  festgelegt. Der direkt nach  -o  stehende Text darf keine Leerzeichen oder Trennstriche enthalten. Die Begrifflichkeit ist grundsätzlich frei definierbar, im Interesse einer guten Auswertbarkeit sollte das Synonym aber nicht gewechselt werden.

•Werden die Parameter  -c  (Category) und   -o  (Owner) mehrfach angegeben, wird nur die jeweils erste Nennung ausgewertet; die Reihenfolge der Nennung ist nicht von Belang.

•Der Beschreibungstext (Description) ist möglichst kurz und prägnant zu formulieren; fehlt der Text zu einem ansonsten gültigen ToDo-Eintrag wird der Hinweistext  "No description found" in der Liste angezeigt.

•MultiLine-Einträge aus maximal 4 aufeinander folgenden Zeilen sind möglich, sofern sie mit  {  oder  (*  eingeleitet werden. Ein MultiLine-Eintrag der in mehreren Zeilen mit jeweils  //  beginnt, wird nicht erkannt (wie ToDoList).

•xx

 

Datascan

•Der primäre Scanbereich wird über die Auswahlfelder bestimmt. Aus den von der IDE übernommenen Dateilisten werden nur Dateien mit den Dateierweiterungen  .dpr   .pas   .inc  und  .todo  auf ToDo-Einträge untersucht. Dateien mit der Erweiterung  .c  werden nicht behandelt. Diese Auswahl ist im Code fest eingestellt und derzeit nicht konfigurierbar (wie ToDoList).

•Die Angabe der Additional directories ist optional; nur die jeweils als aktiv markierten Verzeichnisse werden gescannt. Optional werden auch Unterverzeichnisse eingelesen; mit Doppelklick auf einen Verzeichniseintrag wird die Berücksichtigung von Unterverzeichnissen aktiviert bzw. deaktiviert.

•Die Extensions werden nur für das Einlesen der Dateien der zusätzlichen Verzeichnisse verwendet! Nur die jeweils als aktiv markierten Dateinamenerweiterungen sind für die Auswertung relevant.

•Die Token werden für die Auswertung aller aus den Dateien extrahierter Zeilen verwendet; nur die markierten Token werden für die Analyse genutzt. Die Geschwindigkeit der Syntaxanalyse wird maßgeblich durch die Anzahl der zu Vergleichenden Token bestimmt, daher sollte immer nur die tatsächlich relevante Menge von Token für die Analyse aktiviert werden. Folgende Aussagen anpassen /erweitern, wenn neuer Scan einsatzbereit:

TODO 3 findet nur TODO 3, TODO findet TODO und TODO 3 - es wäre daher unsinnig ToDo X und gleichzeitig ToDo zu aktivieren.

Auch ein mit  //  eingeleiteter ToDo-Eintrag hinter einem mit  //  auskommentiertem Befehl wird gefunden.

•xx

Ein Standard-ToDo-Eintrag besteht aus Einleitung // oder (* oder { gefolgt von einem Token, optional einer Priorität, einer Kategori, einem Besitzer, einem Doppelpunkt und einem Erläuterungstext.

•Sofern es verschiedene Rahmenbedingen (Arbeitumgebungen) gibt, alle relevanten Token definieren und nur bei Bedarf in der Konfiguration von ToDoGrid aktivieren (> scheiße formuliert, ÄNDERN)
