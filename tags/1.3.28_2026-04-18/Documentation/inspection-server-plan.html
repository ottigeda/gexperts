GExperts UI Inspection Server

Context

When tracking down display/DPI scaling problems in GExperts forms, there is currently no way to see or inspect the running UI inside the Delphi IDE from the command line. This plan adds a lightweight TCP inspection server embedded in the GExperts DLL that lets an external CLI tool query form/control properties and take screenshots. Testing inside the actual IDE catches real-world issues that standalone testing would miss.

Protocol

Line-based text protocol. The client sends one command line (CRLF terminated), and the server responds with multiple lines terminated by an END line.

Commands (Phase 1 — read-only)

CommandDescription
FORMSList all forms (class, caption, bounds, visible, DPI)
CONTROLS <id>Enumerate controls recursively with properties
SCREENSHOT <id> <path>Save form screenshot as BMP to Windows path
BOUNDS <id>Form geometry: position, client size, monitor, DPI
CHECK <id>Automated overlap/clipping detection

<id> matches by form caption (substring) or class name.

TfmUsesExpertOptions "Uses Clause Manager, Configuration" [338,241 329x606] Visible DPI=120
TfmUsesManager "Uses Clause Manager" [100,100 800x600] Visible DPI=96
END

Implementation

1. GExperts DLL side: GX_InspectionServer.pas

A new unit in Source/Framework/ containing:

  • TGxInspectServer — Creates a hidden window via AllocateHWnd and starts a TCP listener thread. Incoming commands are marshaled to the VCL main thread via PostMessage + TEvent synchronization (Delphi 6 compatible, no anonymous methods).
  • TGxInspectThread — Background thread using raw WinSock API. Listens on 127.0.0.1:3580 (localhost only for security). Accepts one client at a time, reads command lines, calls ExecuteOnMainThread, sends responses.

Thread marshaling pattern

[delphi] // TCP thread calls this: function TGxInspectServer.ExecuteOnMainThread(const Cmd: string): string; begin FCritSect.Enter; // serialize concurrent requests try FPendingCommand := Cmd; FResultEvent.ResetEvent; PostMessage(FHiddenWnd, WM_GX_INSPECT, 0, 0); FResultEvent.WaitFor(10000); // 10s timeout Result := FPendingResult; finally FCritSect.Leave; end; end; // Main VCL thread handles the message: procedure TGxInspectServer.HiddenWndProc(var Msg: TMessage); begin if Msg.Msg = WM_GX_INSPECT then begin FPendingResult := ProcessCommand(FPendingCommand); FResultEvent.SetEvent; end else Msg.Result := DefWindowProc(FHiddenWnd, Msg.Msg, Msg.WParam, Msg.LParam); end; [/delphi]

Command handlers (all run on main VCL thread)

  • FORMS — Iterate Screen.CustomForms, output class name, caption, bounds, visible state, DPI.
  • CONTROLS — Find form by caption/class, recursively enumerate Controls[i] for each TWinControl. Output: Name, ClassName, Left, Top, Width, Height, Caption/Text, Visible, Enabled. Indent by nesting depth.
  • SCREENSHOT — Use PrintWindow API to capture the form (including non-client area) into a TBitmap, save as BMP.
  • CHECK — Automated detection of: sibling controls with overlapping bounds, controls extending outside parent client rect, button/label text wider than control width (using Canvas.TextWidth), visible controls with zero width or height.

2. External CLI tool: GxInspect.exe

A standalone console application in Projects/StandAlone/GxInspect/. Simple TCP client that connects to the server, sends a command, prints the response.

GxInspect.exe [options] <command> [args...]
  -p <port>    Server port (default: 3580)

Commands:
  FORMS                              List all forms
  CONTROLS <form-id>                 List controls
  SCREENSHOT <form-id> <filepath>    Save screenshot
  BOUNDS <form-id>                   Form geometry
  CHECK <form-id>                    Overlap/clipping check

3. Activation

The inspection server is opt-in via environment variable. Set GX_INSPECT=1 (default port 3580) or GX_INSPECT=<port> before launching the IDE. The server starts after IDE initialization (in DoAfterIDEInitialized) and stops when GExperts unloads. No registry settings needed.
