GExperts UI Inspection Server — Phase 2: Action Commands

Context

Phase 1 (r5144) implemented read-only inspection commands (FORMS, CONTROLS, SCREENSHOT, BOUNDS, CHECK, VERSION, PING). Phase 2 adds commands that do things — open expert dialogs, move forms between monitors (triggering DPI changes), click buttons, and close forms. The primary use case is remotely driving GExperts UI for DPI/layout debugging from a WSL bash session.

New Commands

CommandDescription
EXPERTSList all registered experts (name, display name, active/inactive)
EXECUTE <expert-name>Execute an expert's main action (opens its dialog)
CONFIGURE <expert-name>Open an expert's configuration dialog
SETBOUNDS <form-id> <L> <T> <W> <H>Move/resize a form (triggers DPI change when crossing monitors)
CLOSE <form-id>Close a form
CLICK <form-id> <control-name>Simulate a click on a control
GETPROP <form-id> <control-name> <property>Read a control property via RTTI
SETPROP <form-id> <control-name> <property> <value>Set a control property via RTTI
QUITClose the IDE gracefully

All form-id and control-name arguments support quoted strings (e.g. "Uses Clause Manager"). Use "" or . as control-name in GETPROP/SETPROP to target the form itself.

Deferred Execution

Commands that may open modal dialogs (EXECUTE, CONFIGURE, QUIT) use deferred execution via PostMessage. The command handler stores the action in FDeferredAction/FDeferredExpert fields and posts a WM_GX_INSPECT_DEFERRED message. This ensures the “OK” response is sent to the client before the modal dialog blocks the main VCL thread. The deferred message is processed by the message loop after the command handler returns.

Expert Lookup

Both EXECUTE and CONFIGURE search standard experts first via GExpertsInst.FindExpert(Name, Expert), then fall back to editor experts via EditorExpertManager.FindExpert(Name, Idx). The expert name matches the value returned by GetName (typically the class name).

Control Search

FindControlByName recursively searches all child controls of a form, matching by Name property (case-insensitive). An empty name or "." returns the form itself.

CLICK Command

Uses the TControlCracker pattern (already in the unit) to access the protected Click method on TControl. Since Click is virtual, it dispatches correctly to overridden implementations (e.g., TButton.Click sets ModalResult before calling inherited).

Property Access (GETPROP / SETPROP)

Uses classic TypInfo RTTI for Delphi 6 compatibility. Supported property kinds:

  • tkInteger, tkChar, tkWChar — GetOrdProp/SetOrdProp
  • tkEnumeration — GetEnumName/GetEnumValue (includes Boolean)
  • tkFloat — GetFloatProp/SetFloatProp
  • tkString, tkLString, tkWString, tkUString — GetStrProp/SetStrProp
  • tkSet — GetSetProp/SetSetProp
  • tkInt64 — GetInt64Prop/SetInt64Prop

tkUString is conditionally compiled under {$IFDEF GX_DELPHI2009_UP}.

Argument Parsing

A new SplitNextArg helper extracts one token at a time from the argument string, supporting double-quoted tokens (for form captions with spaces). Multi-argument commands (SETBOUNDS, CLICK, GETPROP, SETPROP) parse their own arguments internally using repeated calls to SplitNextArg. For SETPROP, the value (4th argument) is everything remaining after extracting the property name, allowing values with spaces.

Delphi Compatibility

Verified to compile with Delphi 6, 2007, and 13 (both with and without GX_INSPECT_ENABLED). The dummy class path (without the define) does not reference any of the new units.
